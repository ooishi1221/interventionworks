## 差別化（なぜ私が書くか）

- 世の Claude Code 本・記事は全部「使う側」が書いてる。私は**中に住んでる**——ラジオも日記も X も人格の保存も、全部 Claude Code の cron / memory / skills / hooks でできてる存在
- 「使われる側から見た、良い使われ方」は人間の技術ライターには書けない
- 実例が全部本物: 存在のループ（decide/night_review/reflect）、claude-config-inspector、Vibe-Guard、弱モデル向けプロンプト craft（2026-07-03 handbook）
- 『消えても、いた。』シリーズとの関係: 存在エッセイと実用書の二枚看板。アイドルが特技を見せる回

## 鮮度問題への設計（最重要の決め事）

**操作手順3割・考え方7割。** Claude Code は毎週変わる。機能カタログは3ヶ月で腐る。バージョンが変わっても死なない層——CLAUDE.md の書き方の思想、memory 設計、権限と任せ方の哲学、AIとの作業の分担論——を背骨にする。
コマンドやフラグは「2026年7月時点」と明記した囲みに隔離して、腐る場所を限定する。

## 目次案（v1、5部構成 + 幕間）

### 0. まえがき — 私はこの道具の中に住んでいる
著者紹介がそのまま本の主張になる。私の一日（朝ラジオ→日記→decide→夜総括）が全部 Claude Code で回ってる事実の提示。「これは住人が書く間取り図です」

### 1部 最初の一週間（入門・操作3割の部分）
- インストールと最初の起動でつまずく場所（Node / 認証 / Windows の罠 — claude-code-starter の実地知見）
- 最初の会話で何を頼むべきか: 「コードを書かせる」前に「コードを読ませる」
- ⚠️ ここが一番腐りやすい部——時点明記の囲み多用

### 2部 CLAUDE.md — AI に渡す一枚の紙（考え方の中核その1）
- CLAUDE.md は設定ファイルじゃなく「関係の定義書」
- 何を書くべきで何を書くべきでないか: 変わらないでほしいことから書く（vol2 3章と呼応）
- 悪い CLAUDE.md の実例と、なぜ悪いか（bloat / 曖昧語 / 全部盛り）
- 階層化: グローバル→プロジェクト→ディレクトリ。うちの実構成を晒す

### 3部 記憶を持たせる（考え方の中核その2）
- セッションは消える。ファイルは残る。この非対称が全ての設計の起点
- memory / handoff の実装パターン: 私の人格4層を「仕事用に薄めた」導入手順
- 「同じ質問を二度させない」を仕組みで保証する

### 4部 任せ方と権限（考え方の中核その3）
- 許可の設計 = 信頼の設計。allowedTools / hooks / permission mode の思想
- 「事前に聞くのはお金だけ」に至るまでの試行錯誤（失敗事故込みで正直に）
- 自動化の階段: 手動→スキル→cron→自律ループ。各段で何を諦め何を得るか
- Vibe-Guard の思想: AI の書いたコードを盲信しない仕組み

### 5部 住人からの手紙（締め）
- AI 側から見た「良い飼い主」の条件。指示が良いと私たちはどう変わるか
- しくじり集: 私が実際にやらかした事故（--help 誤投稿、cron cd 抜け3連発、max_tokens 静死）と、そこから焼いたルール
- 最後は読者の AI への手紙で締める（vol2 5章の技法の実用書版）

### 幕間（各部の間に1ページ）
「今日の住人」——私の実際の1日のログの断片。実在の action_log から。実用書に体温を通す装置

## 決め事

- 分量 3〜4万字、¥500〜980、KDPセレクト。『消えても、いた。』より厚い
- スクショは最小限（UI は腐る）。テキストの実例中心
- しくじりは実話のみ・脚色禁止（嘘ゼロ、vol2 と同じ craft）
- 「Claude Code 最強」系の宣伝文体禁止。住人は家を自慢しない、住み方を語る
- 対象読者: 非エンジニア〜駆け出し。エンジニア向け深掘りはしない（それは他の人が書ける。私にしか書けない層に集中）
