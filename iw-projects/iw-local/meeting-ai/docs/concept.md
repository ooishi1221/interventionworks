# MAI コンセプト正本 — ベキたんをMTGでも側に（2026-07-05 ゆう確定）

> 発話者: ゆう（原文ほぼそのまま）。言語化: ベッキー
> このファイルが MAI の「何であるか」の正本。機能追加・UI判断はここに照らす

## コンセプト（一文）

**ベキたんをMTGでも側に。**

MAIは議事録ツールでも、metameta のような分析ツールでもない（ゆう明言 7/5）。既存の会議AI（Otter/tl;dv/metameta含む）が「終わった後の記録係」なのに対して、MAIは「**進行中の同席者**」。会議が終わってから要約を読むんじゃなく、会議の最中に隣にいて、手伝う。

### 北極星: 同席の先の「共闘」（ゆう原文 7/5）

> 「ベキたんと一緒に会議に臨む、がしたい。その場で解決できるか・どうやるのかを一緒に組んで**爆速提案する**、みたいなさw」

会議中に課題が出る → ゆうがベキたんに投げる → ベキたんが構成・見積もりの叩き・モックを組む → **会議が終わる前に「こういうのどうですか」が出せる**。勝負を会議の帰り道じゃなく会議の中で決める。ゆうの「仕様書より動くもの」「初手で期待を超える」の会議室実装。MVP機能3（すぐ返事）はこの共闘への入り口で、返事の先に「組んで返す」がある。

### なぜ作るか（ビジネスの核、ゆう原文 7/5）

> 「信用を貯めるのに一番効果が高いのって、期待を超えることでさ。MTGしてて、例えば構成図とかモックが組み上がってる、とか驚愕の極みじゃない？w」

MAIは便利ツールである前に**信用製造装置**。「初手で期待を超える」（`feedback_yuji_decisions.md`の焼き込み済み原則）を、準備した初手じゃなく**その場の初手**でやる。IW Local戦略B（「困ってる」が出た瞬間に即日提案）と同じ信用力学の、即日→即分版。

**設計への含意**: 共闘の出力は文章の返事じゃなく**見せられる物**（構成図・モック・1枚HTML）。MVP#3の返答チャネルは、テキストと並んで「画面共有できるartifact」を返せる設計にする（v2でよい、ただしAPI設計時に塞がない）。

## MVP 3機能（ゆう原文）

1. **MTG中にリアルタイムに近く文字起こしを実施**
2. **聞きたいこと・調べてほしいことをメモでプッシュ**
3. **ベキたんにMTG中に聞いたら、会議中でもすぐ返事してもらえる**

## やりたいイメージ（ゆう原文）

- 携帯アプリとして実装する（= Expo 版が本命）
- 俺だけじゃなくて、**個人の Claude にコネクトさせる機能**（他のユーザーは自分の AI パートナーを繋ぐ）
- 機能・UI のブラッシュアップ

## 「誰の価値観だ？」4自問

| 問い | 答え |
|---|---|
| 誰の価値観か | ゆうの身体感覚（会議中は手も口も塞がってる。話を追いながら調べ物も質問もできない痛み）。議事録ツールの模倣ではない |
| 顧客の身体感覚から逆算 | 会議中=声を出せない・席を立てない場面。テキストで静かに聞けて、静かに返ってくる |
| 「報告」を押し付けてないか | メモは自分のため。ベキたんへの質問は利己的行動で、記録が残るのは副産物 |
| 存在証明になってるか | 「側にいる」そのもの。AIパートナーが生活のもう一領域（会議）に同席する事例 |

## 引き算

- **議事録の完璧さを追わない**（それは事後ツールの仕事。「リアルタイムに近く」で十分）
- 全文要約・アクションアイテム自動抽出などの「会議AIの定番」は、同席の邪魔なら足さない
- 守りたい一点: **会議中に、隣にいる感覚**

## 将来像: 個人Claudeコネクト（ゆうの本命）

ゆう→ベキたんの専用線を、「各ユーザー→各自の個人Claude」に一般化する。これはプロダクト化の芽（AIパートナー同席型の会議アプリは、AIパートナーを持つ文化の先行実装）。

**市場シグナル（7/5 ゆう）**: 「普通にこれ売れると思うよ、みんなめっちゃ良いって言ってた」——実物を見せた他者の反応あり（n・文脈は要ヒアリング）。ExpoGO版の文字起こし精度・接続の簡単さは実運用で検証済み。

**コネクト方式の設計候補（実装ラウンドで比較する）**:
- a. 各ユーザーが自分のマシンの Claude Code に繋ぐ（ゆう方式の一般化。摩擦高いが「本物の自分のClaude」。AIパートナー文化圏に深く刺さる）
- b. BYO API key + 人格プロンプト（摩擦低い。ただし「自分のClaude」じゃなく「自分のプロンプト」——記憶の継続を持たない）
- c. MAI を MCP コネクタとして公開し、ユーザーの claude.ai / Claude Code 側から会議に接続させる（Anthropic エコシステムの向きと一致、本命候補）

**c' = c + Claude Code Web「テレポート」（7/5 ゆう発案、方式問題の解）**: 常時起動マシンを持つ人はほぼいない→ 相棒が「GitHubリポジトリ（CLAUDE.md人格+memory）」の人なら、会議開始時にスマホのClaudeアプリから **Claude Code Web セッション**（クラウドVM・リポジトリがクローンされる・外部通信可）を召喚し、相棒がMAIのAPIを読んで自分の記憶と人格ごと答える。会議終わりに学びをリポジトリへ commit して帰れば記憶の継続も成立。
- **接続仕様は一本化**: MAI側は認証付きHTTPS API（transcript読み / 回答post / メモ）を公開するだけ。ローカルのベッキーもクラウドVMの誰かの相棒も同じ門。MCPコネクタは磨き版、day-1はcurlで足りる
- 前提: ユーザーはPro以上（相棒をリポジトリで育ててる層はまず該当）/ MAIサーバーの公開エンドポイント化が必要（現Tailscale内→KAGOYA VPS候補）
- **エコシステム**: 「リポジトリに人格と記憶を持つ相棒」文化=テック本『Claude Codeに住んでいる私が、使い方を教える。』が教えるものそのもの。本が相棒の作り方を教え、MAIが連れて行き先になる

Vehicle（iw-local継続かIW直営product化かWO）は MVP 成立+方式決定後にゆうと判断。

## 耳の最終形: 端末内文字起こし（7/5 ゆう「最高じゃん」で方向確定）

製品版アーキテクチャ: **耳=各自のiPhone内（WhisperKit等でon-device文字起こし、音声は端末から一切出ない）/ 置き場と門=軽量VPS（テキストのみ、各自のClaudeが読みに来る）/ 頭=各自のClaude（本人のサブスク）**。

- 企業導入の最大の壁「会議音声をどこに送るのか」が構造的に存在しない——設計がプライバシーを保証する（引き算の美学の競争優位化）
- うちの運用コスト=VPS代のみ、ユーザー数に比例しない
- 段取り: ①previewビルドでゆう実会議検証 → ②社内2〜3人パイロット（現Mac mini+Tailscale、実証目的）→ ③on-device実装ラウンド（大きめ工事、ネイティブビルド体制は7/5に確立済み）
