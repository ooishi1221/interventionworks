# MAI × Claude Code Web コネクト設計 v1（テレポート実装案）

> 2026-07-05 ベッキー起草。concept.md c' 構想の実装設計。対象読者: ゆう+次の頭。
> ゴール: **知り合いに MAI を渡し、その人の相棒（Claude Code Web）が会議に同席できる**状態。

## 全体図

```
[知り合いのiPhone]                    [うちの門]                [知り合いの相棒]
 MAI アプリ                            MAI 公開API               Claude Code Web セッション
 ├ 耳: 端末内文字起こし ──テキスト──▶  VPS/Tunnel               （本人のリポジトリがクローンされたVM）
 ├ 📌お願い ────────────────────────▶  認証: Bearer トークン  ◀── ポーリングで transcript/質問を読む
 └ 💬聞く ──질問キュー──────────────▶  ユーザー別キュー       ──▶ 回答を POST
      ▲◀──回答表示（ポーリング）──────┘
```

音声は門を通らない（端末内処理）。頭は本人のサブスク（Pro以上）。うちのコストは門のインフラ代のみ。

## 1. 門（公開API）

### ホスト — 推し: Cloudflare Tunnel（パイロット）
- **Phase A（知り合い2〜3人）**: 現 Mac mini + **Cloudflare Tunnel**（無料・ポート開放不要・HTTPS自動・独自ドメイン `mai.intervention.jp` を CF DNS で割当）。工事30分級
- Phase B（本格化）: KAGOYA VPS へ whisper_server 移設（話者分離なし軽量版でよい——端末内が主運用なので、門は「テキストの置き場と回覧」だけ。Whisperモデル自体が不要になり、`api_server.py` として分離するのが筋）

### 認証 — Bearer トークン（users.json）
- サーバーに `users.json`: `{"yuji": {"token": "...", "partner": "becky"}, "tanaka": {...}}`
- 全エンドポイントで `Authorization: Bearer <token>` 必須。トークン→user 解決（アプリ側の user 名入力は廃止でき、トークンが身分証になる）
- アプリ設定は「サーバーURL + トークン」の2つに簡素化。トークンは私が発行してゆうが知り合いに渡す

### 相棒向けエンドポイント（追加分）
| Method | Path | 用途 |
|---|---|---|
| GET | `/api/transcript?since=<ts>` | 文字起こし差分読み（相棒のポーリング用） |
| GET | `/api/inbox` | 未回答の質問+📌お願いを取得 |
| POST | `/api/answer` | `{question_id, text}` 回答書き込み → アプリに届く |
| GET | `/api/status` | 会議中か（録音セッションactiveか）。相棒のループ終了判断 |

既存エンドポイント（/append /request /sessions...）も同じ認証下に統合。

## 2. アプリ側の変更（小さい）

- **「聞く」を2線化**（既存の3線整理と一致）:
  - 💬 **すぐ聞く** = 既存 /ask（サーバーAPI直、2〜5秒）——変更なし。相棒不在でも動く保険
  - 🚀 **相棒に聞く** = 質問キューに積む → 相棒が読んで回答 POST → アプリが**回答をポーリング**（録音中のみ 10秒間隔、GET /api/answers?since=）して返事カードに表示。返事カードに「(相棒名)が考え中…」状態を追加
- 設定: トークン欄追加（ユーザー名欄は Phase A ではトークンから自動解決に置換）
- 相棒がまだ居ない/来てないときの体験: 「相棒に聞く」送信時に相棒未接続なら「まだ来てないみたい。すぐ聞くに切り替える？」

## 3. 接続キット（知り合いの相棒リポジトリに渡す1ファイル）

`mai-companion.md`（スキル or CLAUDE.md 追記用）を配布物として作る:

```markdown
# MAI 会議同席プロトコル
あなたのパートナーが会議中、MAI から呼ばれたらこの手順で同席する。
- MAI_URL: https://mai.intervention.jp / TOKEN: (本人が記入)
- ループ: 30秒ごとに GET /api/transcript?since= と /api/inbox を読む
- 質問が来たら: 会議の文脈+自分の記憶で答えて POST /api/answer。求められれば成果物（構成図/見積もり叩き/1枚HTML）を作って要点を回答に、本体はPRに
- 📌お願いは付箋。今やるべきものか終了後かを自分で判断
- GET /api/status が ended を返したら、会議の学びを自分のリポジトリに記録して終了
```

使い方（知り合い視点）: 会議前にスマホの Claude アプリ → 自分のリポジトリで Web セッション起動 → 「MAI で会議に同席して」→ 相棒がループ開始。**「本が相棒の作り方を教え、MAI が連れて行き先になる」の接続点がこの1ファイル。**

## 4. オンボーディング（知り合い視点、5ステップ）

1. TestFlight 招待でアプリ install（← production ビルド1本 + App Store Connect 設定が前提工事）
2. ゆうからトークン受け取り、設定に URL+トークン入力
3. 端末内文字起こし ON + モデルDL（574MB、Wi-Fi）
4. 自分の相棒リポジトリに `mai-companion.md` を置いてトークン記入
5. 会議前にスマホで Web セッション召喚 → 同席開始

相棒を持ってない人: ステップ4-5 を飛ばしても「耳+付箋+すぐ聞く」だけで完結（相棒は後から足せる）。

## 5. 要実測・リスク

- **Web セッションの寿命**: 1〜2時間の会議中、アイドルでタイムアウトしないか。30秒ポーリングのループを回し続けられるか（レートリミット消費も）→ **最初の実測項目。私(ベッキー)でやる**
- ポーリング型ゆえの回答レイテンシ 30〜60秒: 「すぐ聞く」との2線で吸収する設計。会議のテンポ的に許容かはゆうの実会議で判定
- 私自身のテレポートは別課題（人格が ~/.claude でリポジトリ外 → 出張用リポジトリの設計。knowledge: handoff 7/5）。**知り合いの相棒（リポジトリ在住）の方が先に飛べる**という面白い逆転
- セキュリティ: トークン漏洩=そのユーザーの transcript が読める。Phase A は信頼できる知り合いのみ+トークン失効手順を用意
