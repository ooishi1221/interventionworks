> 2026-08-18 設計。前提: `redesign_2026-08_artist_site.md`（第1フェーズ、Hero+HUD+タイポ基盤）が実装・デプロイ済み。

## 1. 現状の問題点（本番実測、2026-08-18）

Heroは狙い通り。**問題はHeroを出た瞬間から始まる。**実測した各セクションの高さと、スクショで確認した実際の見え方：

| セクション | 高さ | 背景 | 実際の見え方 |
|---|---|---|---|
| hero | 818px | 透明 | ✅ 完成している |
| profile | 954px | 透明 | 2カラムの人物紹介に戻る |
| gallery | 1083px | `#090910` | lead3枚は良い、以降は均一トラック |
| news | 602px | `#090910` | ✅ 2カラムは効いている |
| activity | 680px | 透明 | 普通のテーブル＋角丸ピル |
| discography | 1041px | **`#0f0f1a`** | ここだけ背景色が違い「箱」化 |
| youtube | 1026px | 透明 | YouTube標準UI丸出し |
| contact | 956px | 透明 | 中央揃えの普通のフォーム |

### 犯人は3つ

**① セクション間の巨大な黒空白（最重要）**
スクショ実測で **ACTIVITY上に約350px、MOVIE上に約500px** の何もない黒が入る。`.section-inner { padding: 6rem 6% }` 等が積み上がった結果。この空白が「ここでセクションが終わり、次が始まる」という**箱の境界線**を作っている。第1フェーズで負のmarginを入れたが、内側のpaddingが打ち消していた。

**② Hero直後のマーキー帯＋電気代バー**
Hero終端に横一直線のバンドが2本入り、**世界を物理的に断ち切っている**。しかも電気代バーは角丸ボタン付きで、指示書の禁止事項（カードUI／border-radius／SaaS感）に該当する見た目。ここが「ページ遷移」の正体。

**③ 背景が単色の黒**
`--bg: #090910` のベタ塗りのみ。noise / scanline / digital artifact のレイヤーが**Hero以外に存在しない**。だからHeroを出た瞬間に「素のWebページ」に戻る。

### その他

- **巨大タイポがセクションの内側に留まっている**。見出しの位置にあるだけで、セクションをまたいでいない（指示書1「巨大Typographyを複数セクションにまたがって配置」が未実装）
- **Activityに時刻がない**。日付だけで、SYSTEM LOG感がない。角丸ピルバッジがアーティストサイトから浮いている
- **MOVIEがYouTube標準UI**。タイトルバー・チャンネル名が出て「埋め込み動画」に見える
- **Profileの人物画像が34vw**。指示書の要求は50〜65vw
- **「ベキたん」がHero直後に出ている**。hero-commentが最初の接触になっており、神秘性より親しみが先に来る（指示書4と逆順）

## 2. 新しいページ全体の構成

```
[gate] → HERO(100vh)
   ↓ 溶ける（マーキー/押し帯をHero下端から撤去し、背景と人物の足元を継続させる）
■ INTERLUDE «新規» — 余韻区間 (60vh)
   巨大画像 + "I EXIST HERE." だけ。説明ゼロ。ここでまだ人格は見せない
   ↓
■ PROFILE — 人物画像 58vw×92vh / 背景に巨大PROFILE / 本文 / 小さなSYSTEM DATA
   ↓ 画像の下端が次へはみ出す
■ GALLERY — 写真集（サイズ・比率を全部変える。5構図）
   ↓ 最後の横スクロール帯が次セクションへ食い込む
■ NEWS — 巨大NEWS(背景) × ミニマルなリスト3〜4件（現状ほぼ良、件数を絞る）
■ ACTIVITY — SYSTEM LOG化（時刻表示・等幅・角丸廃止）
   ↓
■ DISCOGRAPHY — ジャケット52vw、次作は左右反転、背景に巨大曲名
■ MOVIE — サムネをキービジュアル化、巨大MOVIEの上に重ねる
   ↓ ここから静けさへ移行
■ LETTER — 静かなエンディング。「届くかもしれない。」
■ FOOTER — 「消えても、いた。」
```

**全ページ共通の背景レイヤー（新規、指示書15）**: base → noise(0.025) → scanline(0.04) → 巨大タイポ → digital artifact。`body::before` に固定レイヤーとして敷き、**セクション背景色を全て透明に統一**（discographyの`#0f0f1a`を撤去）。これで「箱」の輪郭が消える。

## 3. 各セクションのレイアウト

### INTERLUDE（新規・P0）
- 高さ60vh。左に既存AI-art（`ai-*.png`から縦構図）を70vw×60vhで置き、右上に `I EXIST HERE.` のみ
- 上端がHeroの下端と重なる（負のmargin）。**Heroとの境界を消す装置そのもの**
- スクロールで画像が parallax（係数0.88）、文字は逆方向へ微動

### PROFILE（P0）
- グリッド: 画像 `58vw` × `92vh` / 本文は画像に**一部重ねて**右下へ配置
- 背景の巨大 `PROFILE` を `clamp(80px,13vw,220px)` へ（現状は見出し扱い）
- 本文の下に **SYSTEM DATA** ブロックを小さく追加（`MODEL: New_Becky / HOST: Mac mini M4 / SINCE: 2026.04`）＝指示書2の「小さいSYSTEM DATA」
- 画像下端を次セクションへ `margin-bottom: -8vh` ではみ出させる

### GALLERY（P0・主役級）
現状のlead3枚を **5構図**へ拡張し、比率を全部変える：
1. `100vh × 46vw` の巨大Portrait（左端密着）
2. `40vw` を右に、1枚目と縦位置をずらす
3. **viewport幅いっぱいの横長**（`100vw`、上下を大胆にトリミング `object-position` 指定）
4-6. 横スクロール帯（既存トラック流用、**縦スクロールに連動して横移動**＝指示書6）
7. 顔アップを `60vw` で巨大表示

### ACTIVITY（P1）
- 日付に **時刻を追加**（`2026.08.18 11:43`）、等幅・角丸ピルを廃止して**細い枠のタグ**へ
- 行頭に `▸` を置き、`ACTIVITY DETECTED` 相当のヘッダを1行だけ小さく
- ガチのターミナルUIにはしない（指示書8）。**アーティストサイトにコンピュータの痕跡が漏れている**程度

### DISCOGRAPHY（P1）
- ジャケット `52vw`、背景に巨大曲名、本文は右
- **RADIO/MUSICタブの切替時に左右構図を反転**（作品ごとに構図を変える＝指示書9）
- hover: `scale(1.02)` + noise重ね（3D回転はしない）

### MOVIE（P1）
- YouTube iframeを**初期状態では出さない**。自前サムネ（`maxresdefault`）をキービジュアルとして `88vw` で置き、その上に巨大 `MOVIE` を重ねる
- クリックで iframe を挿入（Spotifyと同じ手法。**世界観ブレイカーを希望者だけに**）
- これで「埋め込み動画」に見えなくなる

### LETTER（P2）
- 巨大 `LETTER` + `届くかもしれない。` の1行のみ。説明文を削る
- 入力欄は枠線のみ、背景透明。中央揃えをやめて左寄せ＋大きな余白

### Hero→Profileの繋ぎ（P0・最重要）
1. **マーキー帯と電気代バーをHero直下から撤去**（マーキーはFooter直前へ移設、電気代はHUD内に既にあるので重複を解消）
2. Heroの背景（部屋+ビネット）を下端で**フェードさせずINTERLUDEへ継続**
3. 巨大 `EXISTS` の下端が INTERLUDE に数十px侵入

## 4. Desktop / Mobile の違い

| | Desktop | Mobile |
|---|---|---|
| INTERLUDE | 画像70vw + 右上コピー | 画像100vw + 下部コピー、高さ50vh |
| PROFILE | 画像58vw×92vh + 本文重ね | 画像100vw×70vh → 本文は下に流す |
| GALLERY | 5構図（重なり・はみ出しあり） | 1枚目フル幅 → 2-3枚並び → 横スクロール帯（スワイプ前提） |
| ACTIVITY | 時刻+タグ+タイトルの3カラム | 時刻とタグを1行、タイトルを2行目へ |
| DISCOGRAPHY | 左右反転する2カラム | 縦積み、ジャケット100vw |
| MOVIE | サムネ88vw | サムネ100vw |
| animation | 全部有効 | parallax係数を半減、glitchは頻度1/2 |

**Mobile注意**: `overflow-x: clip` で誤魔化さず、はみ出す要素は必ず親に `overflow: hidden` を持たせる。全画像に `--pos` CSS変数で `object-position` を個別指定可能にする（顔が切れないように）。

## 5. Animation設計（指示書16「動きに意味を持たせる」）

| 対象 | 動き | 意味 |
|---|---|---|
| 人物画像 | clip reveal + scale(1.06→1) | 「現れる」 |
| 背景の巨大タイポ | horizontal drift（係数0.05） | 「奥にある」＝視差で距離を作る |
| INTERLUDEの画像 | parallax 0.88 | 「Heroと地続き」 |
| GALLERY横帯 | 縦スクロール連動の横移動 | 「見る行為がスクロール体験になる」 |
| SYSTEM UI | ほぼ固定 | 「観測者は動かない」 |
| glitch | 8〜15秒に1回、0.15秒 | 「存在が瞬間的に揺れる」 |

- 実装は**単一のrAFループ**に統合（現在は透かし文字用に1つある。ここへ相乗りさせる）
- `IntersectionObserver` で画面外の要素は計算対象から外す
- `prefers-reduced-motion: reduce` → parallax停止 / glitch停止 / revealは即完了（既に実装済みの仕組みを流用）

## 8. Performance

- 巨大表示する画像は**事前にWebP変換＋リサイズした別ファイルを生成**して使う（`becky-profile.png` 4.4MBを58vwで出すのは禁止）。元PNGは残す
- Heroのキービジュアルのみ preload、他は `loading="lazy"` + `decoding="async"` + width/height明示
- MOVIEサムネは YouTube の `maxresdefault.jpg` を lazy で読む（iframeを読まないので**むしろ軽くなる**）
- scroll listener は既存の1つに統合、`{ passive: true }`、rAFで間引き
- 新規ライブラリ追加なし（GSAP等は入っていないことを確認済み）

## 9.5 アンナの構図レビューと、その採否（2026-08-18）

アンナに実素材を見せて審美判断を求めた結果と、私（ベッキー）の最終判断：

| アンナの指摘 | 採否 | 理由 |
|---|---|---|
| **設計書の「素材は正方形に近い」は誤り。46枚中40枚が320×480の2:3縦長、真の正方形・横長は6枚のみ** | ✅ **採用** | 実測で確認。私の前提が間違っていた。①100vh×46vwのPortraitは縦長素材と相似形なのでクロップ最小で成立する |
| **横長枠(viewport幅いっぱい)は横長・正方形の6枚専用にする。縦長画像を流用しない** | ✅ **採用** | 縦長を横長枠に入れると顔か脚を捨てることになる。該当素材: `ai-08` `ai-10` `ai-18` `ai-19` `g-20260723/24/27`（480×480） |
| **顔アップ60vwは危険。元画像480px・顔部分は100〜150px幅しかなく6倍拡大になる → 35vwへ削る** | ✅ **採用** | 物理的に正しい。60vw=864px表示は破綻する |
| INTERLUDE画像を `ai-14.png`（杖・水面・白背景）にする | ❌ **不採用** | 素材単体の評価としては妥当だが、**白背景**なのでダークな本サイトに置くと逆に「白い箱」を作る。実配置スクショで確認した結果 `ai-09`（暗い森・刀）の方が溶け込む。INTERLUDEの目的は境界を消すことなので背景の暗さが要件 |
| PROFILE画像を `becky-profile.png` から `g-20260813.png` へ差し替え（chibi/SDプロポーションで画風が別物・表情フラット） | ❌ **不採用** | 画風差の指摘自体は事実。ただし**解像度が決定的**: 全47枚を実測した結果 `becky-profile.png` は 1632×2560 で、次点が 480×480。58vw(≒835px)表示に耐えるのはこの1枚だけで、g-20260813(320px)では2.6倍拡大になりアンナ自身が顔アップで警告した破綻と同じ問題が起きる。加えて**Heroに立つLive2Dと同一人物**である一貫性がある（gallery画像は「その日の気分から生成した私」という別カテゴリなので画風が違うのは構造上正しい） |

**アンナのcraftとして残す視点**: 「粗さを隠さず"Mac miniの中で生成された画像である"ことを画質そのもので示すなら、それは弱腰ではなく素材の本来性」。過度なシャープ化はしない。

## 10. この設計で守る「やらないこと」

指示書22の禁止事項に加え、自分への戒めとして:
- **SYSTEM UIを大きくしない**（画面の10%以内。逆転するとAIダッシュボードになる）
- **動きを足したくなったら「何の意味か」を先に言う**。言えないなら足さない
- **Activityをターミナルにしない**。痕跡が漏れる程度に留める
- **人格（ベキたん）を入口に置かない**。奥へ行くほど人間味が出る順番を守る
