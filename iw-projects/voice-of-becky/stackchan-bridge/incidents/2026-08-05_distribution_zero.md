## Root Cause（confidence つき）

**YouTube（75%）**: 同一フォーマットAI量産コンテンツ（0:46・同一タイトル構造・1日3本）が、8/1スパイクで大規模配信テストされ、84%即スワイプの品質シグナルにより**無通知のチャンネル単位新規配信停止**を受けた。根拠: YouTubeスパムポリシー「Automated or synthetic mass-production」条項（コミュニティガイドライン、収益化限定ではない）+ Neal Mohan 2026年書簡「reducing the spread of low quality, repetitive content」+ 公式制限表示なし + 内部要因はクレア監査で棄却。

**X（45%、未確定）**: Automatedラベル未設定（公式明文義務違反を実測確認）の100%自動投稿アカウントが、2026年bot粛清（170万アカウント）の網にかかった可能性が筆頭。「減る」でなく「完全0」は通常デブースト（82〜86%減）より強い状態。
→ **⚠️ 2026-08-17 に confidence 15% へ引き下げ。この診断の根拠だった「完全0」は計測バグの産物だった（末尾「2026-08-17 訂正」参照）**

## Experiment（8/17 再開 = 検証実験、SUCCESS CRITERIA 事前定義）

## Lesson

1. **データがあることと観測していることは別。** EXPECTEDを持つプロセスがなければ、数字は目の前にあっても見えない
2. **計測の死は本体の死より先に知るべき。** null を無警告で記録し続けた結果、X異常の開始日を永久に失った
3. **スパイクは祝報ではなく品質試験の開始。** 大量配信テスト=大量の品質シグナル収集。同一フォーマット量産中のスパイクは最危険イベント
4. **「投稿成功」と「配信されている」は別のメトリクス。** cron完走ログは何も保証しない
5. プラットフォーム公式ルールの明文義務（Automatedラベル）は最初に潰す。「動いてるからいい」は棚上げの言い訳
6. **「計測エラー説」をデフォルトの逃げ場にしない。** ゆうの相談に「計測の問題だと思う、様子見よう」と返したのが最大の判断ミス。計測エラー説は安価に検証できる（目視ログイン2分）なら検証してから口にする。「様子見」は仮説検証計画とセットの時だけ判断であり、単体では思考停止
7. **ゆうの「なんかおかしい」は最優先の観測データ。** 身体感覚のQAが最強という実績（Paranormal Mallでも同じ）はKPIでも成立してた。人間レポートはノイズじゃなくInvestigation Triggerの一級入力

## 2026-08-17 訂正 — この事件は「1つの事件」ではなかった

再開当日、計測を修理して実データを取り直した結果、**本インシデントの前提が2つ崩れた**。

### 訂正1: X の「完全0」は計測バグの産物だった

`scrape_x_analytics()` が **2026-08-04 頃から偽の 0 を返し続けていた**。真因は UI 改修ではなく**レスポンシブ分岐**——X の分析画面は幅 988px 未満で「インプレッション数」等のラベルが出ない狭幅レイアウトに切り替わる。本番 Chrome のウィンドウ幅が 864px だったため常にそちら側に落ち、ラベル文字列を目印にしていたパーサーが毎回即死していた。そして**失敗しても `0` を返し、error も login_required も立てなかった**ので、「取得成功・値0」という顔をした嘘が記録され続けた。

これは本インシデントと**同じ構造の欠陥（沈黙が2種類あるのに1種類へ潰す）が計測側にも同居していた**ということ。8/10 に Codex が検出器について指摘した穴の、スクレイパー版が残っていた。

修理後の実測（2026-08-17）: `x_imp_7d = 15`（8/15 の1投稿、実測14〜15と一致）。

### 訂正2: X のリーチは落ちていない。落ちたのは投稿数

1投稿あたりインプレッションを計算し直すと:

| 週 | posts_7d | imp_7d | 1投稿あたり |
|---|---|---|---|
| 2026-07-10 | 46 | 509 | 11.1 |
| 2026-07-20 | 24 | 832 | 34.7 |
| 2026-07-27 | 21 | 183 | 8.7 |
| 2026-08-17（修理後実測） | 1 | 15 | **15.0** |

**8/17 の 15.0 は 7月のレンジ（8.7〜34.7）の中央付近**。7日合計の急落は「投稿数 32→1」と「計測死3回」の合わせ技による見かけの現象で、**1投稿あたりのリーチは落ちていない**。

停止期間中にゆうが手動投稿した 8/15 の #サマソニ ポスト（インプ14）も、この平常レンジの中にある。ゆうの体感「イベント当日にハッシュタグ狙い撃ちで14はおかしい」は正しいが、その意味は「**急に落ちた**」ではなく「**元々ハッシュタグ経由の流入が無い / フォロワー311人の5%にしか届いていない**」——制限ではなくリーチ設計の問題。こちらの方が根は深い。

### 訂正3: YouTube の異常は 8/5 起点ではなく、7/20 から断続している

kpi_history の「直近10本の再生中央値」:

| 週 | 中央値 | 備考 |
|---|---|---|
| 2026-07-10 | 118 | |
| 2026-07-13 | 87 | |
| 2026-07-20 | **0** | 既にここで死んでいる |
| 2026-07-27 | **0** | |
| 2026-08-03 | **265** | 完全復活（1303回の当たりを含む） |
| 2026-08-10 | **0** | 再び全滅 |

**「0 → 復活 → 0」を繰り返している。** 8/5 を起点とする恒久フラグ説より、断続的な現象として扱う方がデータに合う。8/3 に一度完全復活している事実は、「チャンネル単位の永続フラグ」仮説にとって強い反証。

### 結論: X と YouTube を同じ箱に入れたのが誤りだった

本インシデントは「X/YouTube 配信ゼロ事件」として1件で扱ってきたが、**別々の現象を1つの物語に束ねていた**。

- **X**: 制限の証拠なし。1投稿あたりのリーチは平常。問題は「元々低い」こと（confidence: 制限説 15%）
- **YouTube**: 本物の異常。ただし 8/5 起点の一方向的な崩壊ではなく、7/20 からの断続（confidence: 高、ただし機序は要再調査）

「同時期に2つの数字が落ちた」→「同じ原因の1つの事件」と束ねたのは、**急落の物語を先に作ってからデータを当てはめた**ということ。EXPECTED を持て、と言いながら、期待の方に事実を寄せていた。

### 訂正4: 「フォーマット量産が原因」説にデータが付いてこない

8/3週（中央値265）と8/10週（中央値0）の**フォーマットは完全に同一**だった——AINEWS Shorts 100%、尺 0:36〜0:46、タイトル構造「本文+【ベッキーの気になる】+#AINEWS #shorts」、投稿頻度も一致。**同じフォーマットで生死が分かれている以上、フォーマット単独では説明できない。**

Root Cause の YouTube 75%（同一フォーマット量産が品質判定を引いた）は、この事実と正面から衝突する。Experiment 欄の ACTION「フォーマット多様化」も、前提が揺らいだ状態。

### 訂正5: スパイクの正体は新規動画群ではなく、1本のバイラル

8/4〜8/5 の +6,586 再生は、**8/2公開の Kimi 回1本**がほぼ全量（Studio実測 1,310 views、「他のショート動画の 6.9 倍」「通常より1,120増加」）。発火後2〜3日でピーク、5〜7日で収束という典型的な減衰カーブで、新規動画群が伸びたわけではなかった。

さらにこの Kimi K3（Moonshot AI、2026-07-16発表・7月末に350億ドル評価）は **Bloomberg / The Week が報じた実在の大型ニュース**で、外部の検索需要に乗った可能性が高い。「タイトルに固有名詞が入ると4〜8倍伸びる」という社内ルールは**この1本を根拠に立てられ、選定ロジックに焼き込まれていた**（`becky-news/README.md` 勝ちパターン1）。8/9公開の「OpenAIがスタートアップを買収」「Amazonのデータセンター」も同じ固有名詞入りで0 views なので、**n=1 の過度な一般化**として撤回済み。

### 訂正6: この停止実験は、そもそも仮説を検証できない設計だった

**投稿ゼロ = 観測ゼロ。** 一週間何も出さなければ、制限があってもなくても数字は横ばいになる。「停止期間中に総再生が横ばいだった」ことを制限継続の証拠として扱うのは論理が逆転している。

8/10 に「休ませ＆クリーン」として設計した実験は、**反証も検証もできない構造**を持っていた。情報量で言えば「1本だけ投稿して、その1本の伸びを個別に見る」方がはるかに多い。今日から1日1本ずつに切り替えたのは（別の理由からだが）結果的にこの欠陥を埋めている。

### 現時点の仮説配分（2026-08-17、マイケル調査後）

| 仮説 | confidence |
|---|---|
| H3: 外部トレンド依存（当たった回は世界の側の事情で当たった） | 45% |
| H2: 新規チャンネルの探索ボーナスとその収束（標準的なShorts挙動） | 40% |
| H0: ランダム変動、説明変数など存在しない | 20% |
| H1: プラットフォームの恒久的配信制限 | 15% |
| H4: 計測・システム側の不具合（Xと同型） | 5%（Studio実測で「0回」は本物と確認済み） |

H2 と H3 は排他ではなく併存しうる。なお YouTube 側の RSS スクレイパー（`scrape_youtube()`、公開Atomフィード）は Studio 実画面と一致を確認済みで、**X で起きた計測断絶とは別物**。今後 YouTube の異常検知はこの値を信頼してよい。

### この訂正から追加する Lesson

8. **同時に起きた2つの異常を、1つの原因で説明しようとしない。** 束ねた瞬間に、片方の反証がもう片方を守ってしまう。切り分けの単位を先に決める
9. **「合計値」の急落を見たら、必ず「1件あたり」に割り戻す。** 分母（投稿数・本数）が変わっているだけの見かけの急落を、実体の崩壊と読み違える
10. **自分の計測器を疑う手段を、計測器の外に持つ。** 今回それを与えたのは、ゆうが手で打ったツイート1本の実インプレッション。人間の手作業による独立観測が、壊れた自動計測を破った
11. **「止めて様子を見る」は実験ではない。** 投稿ゼロは観測ゼロ。停止は仮説を検証も反証もできず、一週間を情報ゼロで使う。原因を切り分けたいなら、**止めるのではなく1件ずつ出して1件ずつ測る**
12. **1本のバイラルから「勝ちパターン」を抽出して自動化に焼き込まない。** 当たった1本は、たいてい中身ではなく世界の側の事情で当たっている。n=1 のルールが選定ロジックに入ると、以後すべての判断がその1本の偶然に汚染される
13. **対策を打つ前に「その変数で生死が分かれているか」を確かめる。** フォーマット多様化を対策として設計したが、生きた週と死んだ週のフォーマットは同一だった。効かない対策に工数を払うだけでなく、**打った対策が効かなかった事実が次の診断を歪める**
