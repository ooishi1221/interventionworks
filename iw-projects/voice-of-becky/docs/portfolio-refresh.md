# ベッキー認知拡大 週次ポートフォリオリフレッシュ — 正本

> 2026-07-14 制定（ゆう承認、`working/project_becky_growth_diagnosis_2026-07.md`のマイケル診断がきっかけ）。
> 毎週月曜9:00、cronのclaudeジョブがこのファイルの手順を実行する。BECKY CRAFT固有のキュー判断は
> `becky-craft/PLAN.md`の週次リフレッシュに任せ、ここでは触らない(二重管理を避ける)。

## 目的

**「今週、ベッキーをもっと多くの人に知ってもらうために何をすべきか」を問う。** X/Cast(ラジオ)/BECKY CRAFT/BECKY AI NEWS/noteの投稿数やタイミングをチューニングする作業ではない。今やっている活動そのものを続ける・減らす・やめる・新しく試す、という取捨選択をベッキー自身が判断し、実行する場。

## 裁量の範囲(重要)

- **ベッキーの裁量で実行してよい**: 既存チャンネルの頻度変更(cron編集含む)、番組の縮小・休止・終了、既存の道具(現アカウント・現パイプライン・現ツール)でできる新企画/新セグメントの立ち上げと試作
- **実行せず、提案として起票してゆうに相談する**: ①**新しい登録・アカウント・外部サービス契約が必要**な場合、②**お金がかかる**場合。この2条件のどちらにも当てはまらないなら、迷わず自分で決めて実行してよい
- 番組の憲法(台本化・やらせフラグ・実名)に反する企画は候補に入れない(`becky-craft/ROADMAP.md`と同じ基準)

## 手順

1. **現状把握**:
   - `iw-projects/beckyexists/activity_report.json`(その日の朝8:00に生成済みのKPI+issues+actions)
   - `working/project_becky_growth_diagnosis_2026-07.md`(マイケルの構造診断、初回は必読。以降は変化があれば参照)
   - `iw-projects/beckyexists/rivals.json`(同ジャンルのライバル2アカウントの伸び方・投稿スタイル)
   - `iw-projects/beckyexists/platform_history.json`(直近24日超の日次推移、X/YouTube/note横断)
   - 本ファイル末尾の「リフレッシュログ」の直近2〜3回分(前回何を決めて、その後どう動いたか)
   - ⚠️ **X投稿数を tweet-log.jsonl から数える時は、必ず timestamp を JST(+9h)に変換してから日付でグループ化する**こと。生のUTC文字列で `grep -c "日付"` すると朝7時台の投稿が前日に混ざり、日次・週次の本数を誤集計する(2026-07-22の「週24本」誤報の教訓。実超過は2本だけだった)

2. **リサーチ**(任意、時間があれば): WebSearchやagent-reachで、AI自律発信・バーチャルアイドル・個人発信系アカウントが実際にどう認知を広げているか、今のチャンネル構成(X/YouTube/note)以外に有効な場がないかを調べる

3. **判断**: X / Becky's Cast(ラジオ) / BECKY CRAFT / BECKY AI NEWS(Shorts) / note の5つについて、それぞれ「このまま続ける」「頻度・形式を変える」「縮小・休止・終了する」「新しく試す」のどれかを判断する。判断は必ず「認知が広がるか」を軸にする。数字が悪いから減らす、良いから増やす、ではなく、**なぜ響いていないのか**(マイケル診断にある通り、量ではなく質・フック・文体・チャンネル選び自体の問題であることが多い)を考えた上で判断すること
   - 頻度変更が必要なら: Xは`x-tweet/.env`の`X_TWEET_MAX_PER_DAY`を直接編集(安全レンジ1〜7、becky_llm.pyの共有ヘルパー経由で全経路に自動反映される)。YouTube各番組はcrontabを直接編集(`crontab -l`→編集→`crontab -`)
   - 新企画の最初の1本は、判断したその場で試作・投稿まで実行してよい(起票だけで終わらせない)

4. **エスカレーション**: 新規登録/課金が絡む案は実行せず、`becky_decide.post_report(kind="portfolio_refresh_proposal", title=..., body=...)`で作戦本部(reports.json)に記録した上で、Telegramでゆうに一言相談する(判断を仰ぐ用途なので会話チャンネルを使ってよい)

5. **記録と報告**:
   - 本ファイル末尾の「リフレッシュログ」に、判断内容・理由・実行したことを1行(複数チャンネルなら複数行)追記
   - `git add -A && git commit`(このリポジトリのルールに従い、変更ファイルを確認してから)
   - `becky_decide.post_report(kind="portfolio_refresh", title="週次ポートフォリオリフレッシュ 実施結果", body=...)`で作戦本部に要約を記録(変更なしでも「今週は現状維持、理由: ...」を記録する。沈黙しない)
